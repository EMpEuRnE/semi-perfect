# ชุดเดโมหลังติดตั้ง 006–009

## สิ่งที่ยืนยันกับ Supabase จริงแล้ว

ตรวจแบบอ่านอย่างเดียวในรอบนี้: API ตอบ HTTP 200 และมีภารกิจรายวัน 3 รายการ แต้ม 30/50/60 ตาม brief หน้ารวม /missions ของ production server อ่านข้อมูลจริงและแสดงชื่อทั้งสามได้ ก่อนรันไฟล์ 010 ยังพบรางวัล active เป็นศูนย์ จึงเพิ่มคูปองสาธิตในชุดนี้

ไม่ได้สมัครบัญชี ส่งอีเมล สร้างข้อมูลผู้ใช้ ทดสอบ session หลังล็อกอิน หรือรัน SQL ของเจ้าของโปรเจกต์แทนผู้ใช้

## งานที่ทำต่อให้แล้ว

- หน้า /progress รวม Mission และ Challenge: กำลังทำ รอตรวจ สำเร็จ และสิ้นสุดรอบ แสดง approved progress แยก pending
- Home หลังล็อกอินมีรายการที่กำลังทำ/รอตรวจ พร้อมลิงก์ทำต่อ
- ประวัติรอบรายวันยังเปิดกลับไปดูวันที่ถูกต้องได้
- หน้าแบรนด์แสดงลิงก์หลักฐานและกรอกหมายเหตุได้ ไม่ต้องเดาจากข้อความอย่างเดียว
- ปฏิเสธกิจกรรมต้องระบุเหตุผลอย่างน้อย 2 ตัวอักษร ตรวจทั้ง Server Action และ database trigger
- คูปองสาธิต 3 รายการ: เครื่องดื่ม 20 บาท/100 แต้ม, อุปกรณ์กีฬา 10%/200 แต้ม, คลาสออกกำลังกาย 50 บาท/300 แต้ม ระบุชัดว่าใช้ร้านค้าจริงไม่ได้
- แลกรางวัลจากหน้ารายละเอียด ต้องติ๊กยืนยันใช้แต้มก่อน โหลดยอดแต้มจาก backend และปิดปุ่มเมื่อแต้มไม่พอ
- ใช้ RPC แลกรางวัลเดิมที่ตรวจราคา สต็อก แต้ม และ request ID แบบ atomic ไม่เชื่อราคาจาก client
- ปรับตัวเปิด Windows ให้ติดตั้งแบบ hoisted และเรียก next.cmd โดยตรง ตามวิธีที่ผ่านการแก้ปัญหาของเครื่องผู้ใช้ก่อนหน้า แต่ยังไม่ได้รันตัวเปิดบน Windows จริงในรอบนี้

Progress แสดงสูงสุด 50 รอบ Mission และ 50 Challenge ล่าสุด หมายเหตุปฏิเสธใช้ข้อมูลกิจกรรมล่าสุดสูงสุด 200 รายการ ส่วนยอดรอตรวจดึงจาก aggregate หรือ query pending แยกตาม participation เพื่อไม่ตีความเป็นความคืบหน้าที่อนุมัติแล้ว

## ทำต่อทันที

1. ใน Supabase SQL Editor รัน `supabase/migrations/202610250010_demo_rewards_and_review.sql` อีกไฟล์เดียว โดยฐานข้อมูลต้องติดตั้งถึง 009 แล้ว
2. ไม่รัน INSTALL_FRESH.sql หรือ seed.sql เดิม ไฟล์ 010 รันซ้ำได้โดยไม่สร้างคูปองซ้ำและไม่รีเซ็ตสต็อกเดิม
3. แตก ZIP เปิดโฟลเดอร์ -new ที่มี package.json และ .env.local จากค่าที่ได้รับอนุญาตไว้แล้ว
4. ดับเบิลคลิก START.cmd หรือใช้คำสั่งด้านล่างในโฟลเดอร์ที่มี package.json

```powershell
npm.cmd exec --yes --package=pnpm@11.25.0 -- pnpm install --frozen-lockfile --node-linker=hoisted
```

```powershell
.\node_modules\.bin\next.cmd dev
```

ใช้ Local URL ที่ Terminal แสดง เปิดหน้าต่างนี้ค้างไว้

## เดโมเร็วโดยไม่ต้องตั้งบัญชี Admin ใหม่

ใช้บัญชีสองบัญชีแยกกัน: Brand ในหน้าต่างปกติ และ User ในหน้าต่าง Incognito ห้ามใช้บัญชีเดียวตรวจหลักฐานของตัวเอง

1. Brand สมัคร/ล็อกอิน แล้วเปิดแบรนด์ด้วยแบบฟอร์มยืนยัน
2. สร้าง Campaign และ Challenge เดิน 1 กิโลเมตร ตั้งรางวัลเมื่อสำเร็จ 150 แต้ม วันเริ่มเป็นเวลาที่ผ่านแล้วเล็กน้อย วันสิ้นสุดอนาคต โดย Challenge อยู่ในช่วง Campaign
3. เผยแพร่ Campaign ก่อน แล้วเผยแพร่ Challenge
4. User เข้าร่วมและส่งผล 1 กิโลเมตรพร้อมหลักฐานสาธิตที่ระบุว่าใช้เดโม
5. เปิด Progress: ต้องเป็นรอตรวจและ approved progress ยังไม่เพิ่ม
6. Brand เปิดหลักฐานแล้วอนุมัติ User ต้องเห็น progress สำเร็จและ Wallet เพิ่ม 150 แต้มหลังโหลดหน้าใหม่
7. User แลกคูปองเดโมเครื่องดื่มด้วย 100 แต้ม ต้องเห็นรหัสและประวัติการแลก ยอดเหลือ 50 แต้ม

ภารกิจรายวันส่วนกลางยังต้องใช้ Admin อนุมัติตามสิทธิ์เดิม แบรนด์ตรวจได้เฉพาะ Challenge ของตน ไม่ได้ยกระดับบัญชีใดเป็น Admin อัตโนมัติ

## ผลตรวจ

- lint, typecheck และ production build ผ่าน
- Unit/action/data checks รวม 105 checks ผ่าน
- SQL integration 151 assertions ผ่านใน PGlite พร้อมชุดตรวจ upgrade compatibility ผ่าน
- อ่าน production pages ที่เชื่อม Supabase และตรวจ redirect ของหน้า protected ผ่าน 17 read-only checks รวม /progress โดยไม่ยิง signup หรือส่งอีเมล
- INSTALL_FRESH.sql ติดตั้งครบและมีคูปองเดโม 3 รายการใน PGlite

ยังไม่ได้ทดสอบ browser หลังล็อกอินจริง ภาพ desktop/mobile, Windows launcher จริง หรือหลาย PostgreSQL connections พร้อมกัน การอ่าน public page ผ่านไม่ได้ยืนยันว่าทั้ง signed-in loop ผ่านแล้ว

หลักฐานยังเป็น URL/ข้อความและตรวจด้วยคน ไม่มีอัปโหลดภาพ private Storage หรือ AI ตรวจอัตโนมัติ ชุดนี้เน้น flow ที่เดโมได้โดยไม่ต้องพึ่งอุปกรณ์หรือบริการเพิ่มเติม

ยังไม่ได้รันไฟล์ 010 บน Supabase จริงหรือ push branch ขึ้น GitHub ค่าที่อนุญาตให้ใช้เก็บเฉพาะ .env.local ซึ่งถูก Git ignore ไม่แสดงค่าในรายงาน
